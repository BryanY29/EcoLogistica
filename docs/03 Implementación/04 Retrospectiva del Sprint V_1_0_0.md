## ¿Qué aprendimos?

Durante el Sprint 1 aprendimos la importancia de establecer una estructura de proyecto organizada desde el inicio y de mantener separadas las responsabilidades del backend, frontend y base de datos.

También se reforzó el trabajo con FastAPI, React, PostgreSQL, Docker Compose y herramientas de especificación como OpenSpec. El equipo identificó la importancia de verificar cada componente de manera progresiva antes de realizar la integración completa.

## ¿Qué estamos haciendo bien?

* Se está manteniendo una estructura organizada del repositorio.
* Se están separando las responsabilidades entre backend, frontend y base de datos.
* Se están realizando pruebas sobre las funcionalidades implementadas.
* Se está utilizando Docker para facilitar la configuración de PostgreSQL.
* Se están documentando las especificaciones y decisiones del proyecto.
* Se está manteniendo el enfoque híbrido del proyecto mientras se aplican prácticas de Scrum durante el Sprint.

## ¿Qué podemos hacer mejor?

### Personas

Mejorar la distribución y seguimiento de las actividades para que cada integrante tenga claridad sobre sus responsabilidades y entregables durante el Sprint.

### Relaciones

Fortalecer la comunicación entre los integrantes para informar oportunamente sobre avances, dificultades técnicas y tareas pendientes.

### Procesos

Mejorar la planificación y seguimiento de las tareas para detectar impedimentos con mayor anticipación y mantener actualizados los estados de las actividades.

### Herramientas

Mejorar la configuración inicial del entorno de desarrollo y documentar los procedimientos necesarios para ejecutar Docker, PostgreSQL, FastAPI y React de manera consistente.

### Acciones a realizar

* Mantener actualizado el tablero de trabajo y el estado de las tareas.
* Registrar los impedimentos durante el Sprint.
* Completar progresivamente las funcionalidades pendientes del frontend.
* Ejecutar pruebas y verificaciones antes de cerrar cada funcionalidad.
* Completar la documentación técnica y las instrucciones de ejecución.
* Realizar una verificación integral del sistema antes del cierre del siguiente Sprint.
