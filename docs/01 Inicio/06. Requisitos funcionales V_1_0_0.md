## 2. Marco de Elicitación Holística y Ética

La elicitación de requisitos de EcoLogística se plantea como un proceso sistemático para identificar, analizar, validar y priorizar las necesidades de las personas que participan en la operación logística dentro de El Tambo, Huancayo y Chilca.

El proceso considera tanto las necesidades funcionales como las condiciones operativas, sociales, económicas y ambientales del contexto local.

### 2.1 Fuentes de elicitación

Las principales fuentes consideradas son:

* Entrevistas con responsables de operaciones logísticas.
* Entrevistas con planificadores de rutas.
* Observación de procesos de distribución.
* Revisión de registros de entregas.
* Revisión de problemas relacionados con tiempos y recorridos.
* Encuestas a usuarios potenciales.
* Validación mediante prototipos.
* Retroalimentación obtenida durante iteraciones del proyecto.
* Análisis de restricciones geográficas de El Tambo, Huancayo y Chilca.

### 2.2 Grupos de usuarios considerados

| Grupo                      | Necesidad principal                         |
| -------------------------- | ------------------------------------------- |
| Administrador              | Gestionar usuarios y parámetros del sistema |
| Operador logístico         | Registrar y administrar operaciones         |
| Planificador               | Crear y optimizar rutas                     |
| Conductor                  | Consultar información de sus rutas          |
| Responsable de operaciones | Supervisar indicadores y resultados         |
| Usuario de consulta        | Consultar información autorizada            |
| Auditor                    | Revisar registros y trazabilidad            |

### 2.3 Perspectiva glocal

EcoLogística considera las particularidades del contexto local sin perder los principios generales de los sistemas de gestión logística.

Se consideran:

* Características de movilidad de El Tambo, Huancayo y Chilca.
* Distancias entre puntos de distribución.
* Restricciones de tiempo.
* Capacidad disponible de vehículos.
* Condiciones operativas de los usuarios.
* Disponibilidad de conectividad.
* Necesidades de visualización geográfica.
* Uso responsable de recursos computacionales.
* Reducción potencial de recorridos, combustible y emisiones.

### 2.4 Consideraciones éticas

La definición de requisitos considera:

1. Protección de información de usuarios.
2. Control de acceso según responsabilidades.
3. Trazabilidad de operaciones relevantes.
4. Transparencia en los resultados generados.
5. Evitar decisiones automatizadas sin posibilidad de revisión.
6. Protección de información operacional.
7. Minimización de datos personales recolectados.
8. Accesibilidad para diferentes perfiles de usuario.
9. Uso responsable de información geográfica.
10. Consideración del impacto ambiental de las decisiones logísticas.

# 3. Catálogo de Requisitos Funcionales

## RF-001: Autenticación de usuarios

* **Descripción Atómica:** El sistema debe autenticar a un usuario cuando este proporcione credenciales registradas y vigentes.

* **Prioridad:** Alta

### Criterios de Aceptación

#### Ruta Gold

**DADO** un usuario registrado y habilitado.

**CUANDO** proporciona credenciales válidas.

**ENTONCES** el sistema debe autenticarlo y permitirle acceder a las funcionalidades correspondientes a su rol.

#### Ruta Feliz

**DADO** un usuario registrado.

**CUANDO** proporciona credenciales válidas después de un intento anterior fallido.

**ENTONCES** el sistema debe permitir el acceso y restablecer el contador de intentos fallidos.

#### Ruta Infeliz

**DADO** un usuario registrado.

**CUANDO** proporciona credenciales incorrectas.

**ENTONCES** el sistema debe rechazar la autenticación y mostrar un mensaje indicando que las credenciales no son válidas.

---

## RF-002: Gestión de usuarios

* **Descripción Atómica:** El sistema debe permitir al administrador registrar, consultar, modificar y desactivar usuarios cuando posea permisos administrativos.

* **Prioridad:** Alta

### Criterios de Aceptación

#### Ruta Gold

**DADO** un administrador autenticado.

**CUANDO** registra un usuario con información válida.

**ENTONCES** el sistema debe crear el registro y asignarle el rol seleccionado.

#### Ruta Feliz

**DADO** un administrador autenticado.

**CUANDO** modifica los datos permitidos de un usuario existente.

**ENTONCES** el sistema debe guardar los cambios realizados.

#### Ruta Infeliz

**DADO** un administrador autenticado.

**CUANDO** intenta registrar un usuario con un correo electrónico ya registrado.

**ENTONCES** el sistema debe rechazar el registro y mostrar el motivo.

---

## RF-003: Registro de vehículos

* **Descripción Atómica:** El sistema debe permitir al operador registrar un vehículo cuando proporcione la información requerida.

* **Prioridad:** Alta

### Criterios de Aceptación

#### Ruta Gold

**DADO** un operador autenticado con permisos de gestión.

**CUANDO** registra un vehículo con datos válidos.

**ENTONCES** el sistema debe almacenar el vehículo y dejarlo disponible para las operaciones logísticas.

#### Ruta Feliz

**DADO** un vehículo previamente registrado.

**CUANDO** el operador actualiza sus datos permitidos.

**ENTONCES** el sistema debe guardar la información actualizada.

#### Ruta Infeliz

**DADO** un operador autenticado.

**CUANDO** intenta registrar un vehículo sin los datos obligatorios.

**ENTONCES** el sistema debe rechazar la operación e indicar los campos faltantes.

---

### Criterios de Aceptación

#### Ruta Gold

**DADO** un operador autenticado.

**CUANDO** registra un punto de entrega con información válida.

**ENTONCES** el sistema debe almacenar el punto y asociarlo a las operaciones correspondientes.

#### Ruta Feliz

**DADO** un punto de entrega registrado.

**CUANDO** el operador modifica su información.

**ENTONCES** el sistema debe actualizar los datos permitidos.

#### Ruta Infeliz

**DADO** un operador autenticado.

**CUANDO** proporciona una ubicación inválida.

**ENTONCES** el sistema debe rechazar el registro e informar el error.

---

## RF-005: Registro de pedidos

* **Descripción Atómica:** El sistema debe permitir registrar un pedido cuando el usuario autorizado proporcione los datos necesarios para su distribución.

* **Prioridad:** Alta

### Criterios de Aceptación

#### Ruta Gold

**DADO** un operador autenticado.

**CUANDO** registra un pedido con información válida.

**ENTONCES** el sistema debe almacenar el pedido con estado pendiente de planificación.

#### Ruta Feliz

**DADO** un pedido pendiente.

**CUANDO** el operador modifica información permitida antes de la planificación.

**ENTONCES** el sistema debe guardar los cambios.

#### Ruta Infeliz

**DADO** un pedido.

**CUANDO** falta información obligatoria.

**ENTONCES** el sistema debe impedir el registro y señalar los datos requeridos.

---

## RF-006: Generación de rutas

* **Descripción Atómica:** El sistema debe generar una propuesta de ruta cuando el usuario autorizado solicite la planificación de pedidos pendientes y existan datos válidos.

* **Prioridad:** Alta

### Criterios de Aceptación

#### Ruta Gold

**DADO** pedidos pendientes, vehículos disponibles y puntos de entrega válidos.

**CUANDO** el planificador solicita generar rutas.

**ENTONCES** el sistema debe generar una propuesta de distribución asignando pedidos a vehículos disponibles.

#### Ruta Feliz

**DADO** pedidos pendientes.

**CUANDO** el planificador modifica los parámetros permitidos antes de generar las rutas.

**ENTONCES** el sistema debe generar una nueva propuesta considerando dichos parámetros.

#### Ruta Infeliz

**DADO** pedidos pendientes.

**CUANDO** no existe capacidad vehicular suficiente.

**ENTONCES** el sistema debe informar la imposibilidad de asignar todos los pedidos.

---

## RF-007: Visualización de rutas

* **Descripción Atómica:** El sistema debe mostrar una ruta generada cuando el usuario autorizado seleccione una ruta disponible.

* **Prioridad:** Alta

### Criterios de Aceptación

#### Ruta Gold

**DADO** una ruta generada.

**CUANDO** el usuario la selecciona.

**ENTONCES** el sistema debe mostrar sus puntos de recorrido, pedidos asignados y vehículo asociado.

#### Ruta Feliz

**DADO** varias rutas generadas.

**CUANDO** el usuario selecciona una ruta diferente.

**ENTONCES** el sistema debe mostrar la información correspondiente a la ruta seleccionada.

#### Ruta Infeliz

**DADO** una ruta inexistente.

**CUANDO** el usuario intenta consultarla.

**ENTONCES** el sistema debe informar que la ruta no está disponible.

---

## RF-008: Reoptimización de rutas

* **Descripción Atómica:** El sistema debe generar una nueva propuesta de ruta cuando el usuario autorizado solicite la reoptimización debido a cambios operativos.

* **Prioridad:** Alta

### Criterios de Aceptación

#### Ruta Gold

**DADO** una ruta existente y un cambio operativo registrado.

**CUANDO** el planificador solicita la reoptimización.

**ENTONCES** el sistema debe generar una nueva propuesta considerando la información actualizada.

#### Ruta Feliz

**DADO** una ruta existente.

**CUANDO** el usuario modifica los pedidos incluidos.

**ENTONCES** el sistema debe permitir generar una nueva propuesta.

#### Ruta Infeliz

**DADO** una ruta existente.

**CUANDO** la información necesaria para recalcularla es inconsistente.

**ENTONCES** el sistema debe impedir la reoptimización y mostrar el motivo.

---

## RF-009: Seguimiento del estado de pedidos

* **Descripción Atómica:** El sistema debe permitir consultar el estado de un pedido cuando el usuario posea permisos de consulta.

* **Prioridad:** Media

### Criterios de Aceptación

#### Ruta Gold

**DADO** un pedido registrado.

**CUANDO** un usuario autorizado consulta su estado.

**ENTONCES** el sistema debe mostrar el estado actual del pedido.

#### Ruta Feliz

**DADO** un conjunto de pedidos.

**CUANDO** el usuario aplica un filtro permitido.

**ENTONCES** el sistema debe mostrar únicamente los pedidos que coincidan con el filtro.

#### Ruta Infeliz

**DADO** un pedido inexistente.

**CUANDO** el usuario intenta consultarlo.

**ENTONCES** el sistema debe informar que no existe información disponible.

* **Prioridad:** Alta

### Criterios de Aceptación

#### Ruta Gold

**ENTONCES** el sistema debe actualizar el estado del pedido.

#### Ruta Feliz

**DADO** un pedido asignado.

#### Ruta Infeliz

**DADO** un pedido sin asignación.

**ENTONCES** el sistema debe rechazar la operación.

**ENTONCES** el sistema debe mostrar los indicadores correspondientes.

#### Ruta Feliz

**DADO** un período con información parcial.

**CUANDO** el usuario solicita los indicadores.

**ENTONCES** el sistema debe mostrar los resultados disponibles indicando el período consultado.

#### Ruta Infeliz

**DADO** un período sin información.

* **Prioridad:** Media

### Criterios de Aceptación

**ENTONCES** el sistema debe mostrar los valores calculados para el período seleccionado.

#### Ruta Feliz

**DADO** rutas pertenecientes a diferentes períodos.

**CUANDO** el usuario selecciona un período específico.

**ENTONCES** el sistema debe mostrar únicamente los indicadores correspondientes.

* **Prioridad:** Media

### Criterios de Aceptación

#### Ruta Gold

## RF-014: Registro de auditoría

* **Descripción Atómica:** El sistema debe registrar las operaciones relevantes realizadas por usuarios cuando estas modifiquen información o configuraciones del sistema.

* **Prioridad:** Alta

### Criterios de Aceptación

#### Ruta Gold

**DADO** un usuario autenticado.

**CUANDO** realiza una operación auditable.

**ENTONCES** el sistema debe registrar usuario, operación, fecha y resultado.

#### Ruta Feliz

**DADO** una operación que genera un error.

**CUANDO** el sistema procesa la operación.

**ENTONCES** el sistema debe registrar el evento correspondiente.

#### Ruta Infeliz

**DADO** una operación.

**CUANDO** ocurre una interrupción durante el registro de auditoría.

**ENTONCES** el sistema debe mantener la integridad de la información y reportar el evento.
