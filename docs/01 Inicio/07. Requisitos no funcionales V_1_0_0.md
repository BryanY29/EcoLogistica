# 2. Criterios

Los requisitos no funcionales se expresan mediante escenarios de calidad cuantificables. Cada requisito define una condición verificable y una métrica objetivo.

---

## RNF-001: Rendimiento

**Categoría ISO 25010:** Eficiencia de desempeño.

**Fuente:** Usuario autenticado.

**Estímulo:** Solicitud de consulta de información logística.

**Entorno:** Operación normal con carga máxima definida para el MVP.

**Artefacto:** API de EcoLogística.

**Respuesta:** Procesar la solicitud y devolver los datos solicitados.

**Medida SLA:** El 95 % de las consultas deberá presentar una latencia menor o igual a **1.5 segundos**.

---

## RNF-002: Seguridad

**Categoría ISO 25010:** Seguridad.

**Fuente:** Usuario externo no autorizado.

**Estímulo:** Intento de acceso a un recurso protegido.

**Entorno:** Sistema en operación.

**Artefacto:** Módulo de autenticación y autorización.

**Respuesta:** Denegar la solicitud y registrar el evento.

**Medida SLA:** El **100 % de los endpoints protegidos** deberá requerir autenticación y autorización antes de permitir operaciones restringidas.

---

## RNF-003: Disponibilidad

**Categoría ISO 25010:** Fiabilidad.

**Fuente:** Usuario del sistema.

**Estímulo:** Solicitud de acceso durante el horario operativo.

**Entorno:** Ambiente de producción.

**Artefacto:** Sistema EcoLogística.

**Respuesta:** Permitir el acceso al servicio.

**Medida SLA:** Disponibilidad mensual mínima de **99.0 %** durante el período operativo definido para el proyecto.

---

## RNF-004: Integridad de datos

**Categoría ISO 25010:** Fiabilidad.

**Fuente:** Usuario autorizado.

**Estímulo:** Creación o modificación de información.

**Entorno:** Operación normal.

**Artefacto:** Base de datos.

**Respuesta:** Persistir información consistente.

**Medida SLA:** El **100 % de las operaciones confirmadas** deberá mantener las relaciones e integridad referencial definidas.

---

## RNF-005: Usabilidad

**Categoría ISO 25010:** Usabilidad.

**Fuente:** Usuario operativo.

**Estímulo:** Ejecución de una tarea funcional del sistema.

**Entorno:** Interfaz web.

**Artefacto:** Interfaz de usuario.

**Respuesta:** Permitir completar la tarea.

**Medida SLA:** Al menos **80 % de los usuarios evaluados** deberá completar las tareas principales del MVP sin asistencia externa durante las pruebas de aceptación.

---

## RNF-006: Compatibilidad

**Categoría ISO 25010:** Compatibilidad.

**Fuente:** Usuario.

**Estímulo:** Acceso mediante navegador web.

**Entorno:** Navegadores compatibles definidos para el MVP.

**Artefacto:** Aplicación web.

**Respuesta:** Renderizar y permitir ejecutar las funcionalidades principales.

**Medida SLA:** El **100 % de las funcionalidades principales** deberá operar en las versiones soportadas de Chrome, Edge y Firefox definidas por el equipo.

---

## RNF-007: Mantenibilidad

**Categoría ISO 25010:** Mantenibilidad.

**Fuente:** Equipo de desarrollo.

**Estímulo:** Solicitud de modificación de una funcionalidad.

**Entorno:** Entorno de desarrollo.

**Artefacto:** Código fuente.

**Respuesta:** Permitir realizar la modificación sin alterar funcionalidades no relacionadas.

**Medida SLA:** Al menos **80 % de las pruebas automatizadas existentes** deberán continuar aprobadas después de cada modificación funcional.

---

## RNF-008: Escalabilidad

**Categoría ISO 25010:** Eficiencia de desempeño.

**Fuente:** Usuarios concurrentes.

**Estímulo:** Incremento de solicitudes.

**Entorno:** Carga controlada.

**Artefacto:** Backend.

**Respuesta:** Procesar las solicitudes sin degradación superior al umbral establecido.

**Medida SLA:** El sistema deberá soportar al menos **50 usuarios concurrentes** durante las pruebas de carga del MVP.

---

## RNF-009: Recuperabilidad

**Categoría ISO 25010:** Fiabilidad.

**Fuente:** Infraestructura.

**Estímulo:** Interrupción inesperada del servicio.

**Entorno:** Ambiente de producción.

**Artefacto:** Aplicación y base de datos.

**Respuesta:** Recuperar el servicio y conservar la información confirmada.

**Medida SLA:** El tiempo objetivo de recuperación será **RTO ≤ 30 minutos** y la pérdida máxima aceptable de datos será **RPO ≤ 15 minutos**.

---

## RNF-010: Auditoría

**Categoría ISO 25010:** Seguridad.

**Fuente:** Usuario autenticado.

**Estímulo:** Ejecución de una operación auditable.

**Entorno:** Sistema en operación.

**Artefacto:** Registro de auditoría.

**Respuesta:** Registrar el evento.

**Medida SLA:** El **100 % de las operaciones definidas como auditables** deberá generar un registro de auditoría.

---

## RNF-011: Privacidad

**Categoría ISO 25010:** Seguridad.

**Fuente:** Usuario del sistema.

**Estímulo:** Consulta de información personal.

**Entorno:** Sistema operativo.

**Artefacto:** Módulos de usuarios y operaciones.

**Respuesta:** Mostrar únicamente la información autorizada.

**Medida SLA:** El **100 % de las pruebas de control de acceso** deberá impedir el acceso a información no autorizada.

---

## RNF-012: Eficiencia energética

**Categoría:** Sostenibilidad / Eco-Design.

**Fuente:** Sistema.

**Estímulo:** Procesamiento de consultas y generación de rutas.

**Entorno:** Operación normal.

**Artefacto:** Servicios de aplicación y base de datos.

**Respuesta:** Ejecutar las operaciones utilizando recursos computacionales necesarios.

**Medida SLA:** Las consultas de lectura principales deberán ejecutarse con un máximo de **2 consultas principales por operación funcional**, salvo operaciones de procesamiento que requieran múltiples consultas justificadas.

# 4. Estrategia de validación

Los RNF serán validados mediante:

* Pruebas de rendimiento.
* Pruebas de carga.
* Pruebas de seguridad.
* Pruebas funcionales.
* Pruebas de usabilidad.
* Pruebas de compatibilidad.
* Pruebas de recuperación.
* Revisión de registros de auditoría.
* Análisis de consultas de base de datos.
