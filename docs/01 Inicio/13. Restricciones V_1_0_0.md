# 2. Objetivo

Este documento identifica restricciones que pueden afectar el desarrollo, operación y evolución de EcoLogística.

# 4. Restricciones por dimensión

## 4.1 Salud y Seguridad Pública

La información almacenada puede incluir datos relacionados con usuarios y operaciones.

### Mitigación

* Autenticación.
* Autorización.
* Cifrado de comunicaciones.
* Protección de credenciales.
* Auditoría.
* Minimización de información personal.

---

# 4.2 Costo del Ciclo de Vida

El proyecto debe considerar los costos acumulados de:

* Desarrollo.
* Hosting.
* Base de datos.
* Servicios externos.
* Mantenimiento.
* Actualizaciones.

### Mitigación

Se priorizarán:

* Software de código abierto.
* Arquitectura modular.
* Infraestructura dimensionada según demanda.
* Servicios gratuitos o de bajo costo durante el desarrollo académico cuando sea posible.

---

# 4.3 Cero Carbono Neto y Sostenibilidad

El sistema no puede garantizar por sí mismo cero emisiones netas, debido a que la infraestructura tecnológica depende de proveedores y fuentes energéticas externas.

Por ello, el objetivo del diseño será **reducir el consumo computacional innecesario**.

### Estrategias

* Optimización de consultas SQL.
* Índices adecuados.
* Reducción de procesamiento redundante.
* Uso eficiente de recursos.
* Procesamiento bajo demanda.
* Eliminación de operaciones innecesarias.
* Monitoreo progresivo del consumo cuando la infraestructura lo permita.

---

# 4.4 Aspectos Culturales, Sociales y Económicos

Los usuarios pueden presentar diferentes niveles de experiencia tecnológica.

### Estrategias

* Interfaz clara.
* Formularios con validaciones.
* Mensajes de error comprensibles.
* Pruebas con usuarios.
* Capacitación inicial.
* Iteraciones de mejora.

---

# 4.5 Accesibilidad

La interfaz deberá considerar criterios de accesibilidad.

Como referencia inicial se utilizarán criterios de **WCAG 2.1 nivel AA**, especialmente:

* Contraste adecuado.
* Navegación mediante teclado.
* Etiquetas para formularios.
* Mensajes de error identificables.
* Estructura semántica.

---

# 4.6 Restricción geográfica

El alcance inicial del sistema se limita a:

```text
El Tambo
Huancayo
Chilca
```

No se contempla Lima ni otros ámbitos geográficos dentro del MVP.

La ampliación a otras zonas deberá considerarse como una evolución posterior y requerirá evaluación de impacto.

# 6. Estrategia de gestión de restricciones

Las restricciones serán revisadas durante las iteraciones del proyecto.

Cuando una restricción cambie:

1. Se registrará el cambio.
2. Se analizará su impacto.
3. Se evaluarán alternativas.
4. Se actualizarán los documentos afectados.
5. Se registrará la modificación en Git.
6. Se comunicará a los interesados correspondientes.
